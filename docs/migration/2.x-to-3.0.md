# Moving from 2.x to 3.0

This guide says what changes when you move from the 2.x line (last stable:
2.17.1) to 3.0.0, for each way of using mcp-legal-it. The short release notes,
in Italian and English, are in [`docs/release-notes/3.0.0.md`](../release-notes/3.0.0.md).

> **Draft for the 3.0.0 release.** It describes the 3.0 work merged or open
> for merge as of 2026-10-21 (PRs #55-#62). The VisuaLex migration is still
> running: the Normattiva text channel (the text of a norm will come from
> Normattiva's HTML page by default, instead of Akoma Ntoso first: it arrives
> with migration step 3a), the act index and Akoma Ntoso, then EUR-Lex,
> decisions, citations/URN and vigenza. Those steps can still change what a
> reader returns; this guide will be updated with them before the GA.
> Points that wait for a decision by the project owner are marked
> **pending decision** and describe the question, never an answer.

## 1. What does not change

- **Tool names, parameters and outputs.** The 228 tools keep their names and
  signatures. The few answers that change are listed in §6, each with its
  reason.
- **The launcher.** The plugin starts the server exactly as 2.17.0 does
  (`uv run --frozen --no-sync` from `plugin/server/uv.lock`, through
  `bootstrap.py`). Nothing to install, nothing to configure.
- **Privacy.** The server still runs on your computer, still sends nothing
  to the project, and still queries each public source directly. What 3.0
  adds is control: see `LEGAL_BROCARDI=off` (§2.4) and the network rules
  (§5.2).
- **The data tables** (FOI indices, legal rates, TEGM, D.M. 55/2014 tables...)
  are the 2.17.0 ones. The 3.0 line was realigned with 2.17.0 before any 3.0
  work (#55), so nothing shipped in 2.13-2.17 is lost.

## 2. Claude Code plugin users

### 2.1 Updating

If auto-update is on (`/plugin` → **Marketplaces** → `mcp-legal-it` →
**Enable auto-update**), 3.0 arrives by itself once it is published. To
update by hand, in a terminal:

```bash
claude plugin marketplace update mcp-legal-it
claude plugin update legal-it@mcp-legal-it
```

Then close and reopen Claude Code. The first start of 3.0 downloads the new
locked dependencies once (seconds to a couple of minutes, as on a first
install); later starts take under a second. `/mcp` must show **legal-it**
as *connected*.

To check what you are running, ask Claude to call `stato_server`: it reports
the package version (`3.0.0`), the active tool count, the profile and the
Brocardi switch.

### 2.2 What you see

- The same 228 tools, the same 30 skills, 9 slash commands and 6 agents.
- Some answers change on purpose (§6). The ones a lawyer is most likely to
  meet: `cite_law` reads «D.Lgs. 196/2003 art. 13» correctly, a range such as
  «art. 3-5 c.c.» is refused, `verifica_citazioni` no longer reports a Corte
  costituzionale decision as «inesistente», and
  `termini_esecuzioni(tipo="opposizione_esecuzione")` returns an error.
- A stricter citation gate (§2.5).

### 2.3 Profiles, before and after

`LEGAL_PROFILE` narrows the tool list for hosts that show every tool to the
model. In 3.0 every tool carries exactly one *kind* (`normativa`,
`giurisprudenza`, `autorita`, `registri`, `calcolo`, `redazione`,
`diagnostica`), and the profiles are defined on those kinds and on subject
areas. Every profile now includes the diagnostics. The tag vocabulary and the
full tool table are in [`docs/tool-tags.md`](../tool-tags.md).

| Profile | 2.x | 3.0 | What changed |
|---|---|---|---|
| `full` (default) | 228 | 228 | — |
| `sinistro` | 81 | 79 | − TMview (3), + `stato_server` |
| `credito` | 91 | 89 | − TMview (3), + `stato_server` |
| `penale` | 53 | 51 | − TMview (3), + `stato_server` |
| `fiscale` | 66 | 66 | — |
| `normativa` | 69 | 70 | + `stato_server` (TMview kept) |
| `privacy` | 66 | 64 | − TMview (3), + `stato_server`; Garante kept |
| `studio` | 73 | 76 | + `stato_server`, `verbale_mensile`, `backlog_riconciliazione` |
| `redattore` | 86 | 76 | − TAR/CdS (4), CGUE (4), TMview (3), + `stato_server` |
| `cowork` | 79 | 77 | − TMview (3), + `stato_server` |

The tools that leave a profile were there only because of a wrong
`normativa` tag. The plugin uses `full` unless you set `LEGAL_PROFILE` in the
environment Claude Code starts from. If you filter tools by tag in your own
host, update the filters: TAR/CdS and CGUE tools are tagged
`giurisprudenza`, `costituzionale` became `giurisprudenza_cost`, the Garante
tools are `autorita` + `garante`, CONSOB is `autorita` + `consob`, TMview is
`registri` + `marchi`, and the EU-transposition tools are `normativa` +
`recepimento_ue`.

### 2.4 Running without Brocardi: `LEGAL_BROCARDI=off`

Brocardi.it is the only private source the server uses: doctrinal notes and
case-law abstracts, never the text of a norm. It stays on by default. To
switch it off, start Claude Code with the variable set:

```bash
LEGAL_BROCARDI=off claude
```

(also accepted: `0`, `false`, `no`). Or put it in the `env` block of
`~/.claude/settings.json`. Then:

- `cerca_brocardi` and `fetch_law_annotations` disappear (228 → 226 tools;
  every profile that contains `normativa` shows two fewer);
- no request reaches brocardi.it;
- `cite_law(include_annotations=True)`, `giurisprudenza_articolo` and
  `mappa_orientamento` keep working and say «Brocardi disattivato in questa
  installazione (LEGAL_BROCARDI=off)».

`stato_server` reports the state: use it to confirm the variable reached the
server.

### 2.5 The citation gate

The plugin's Stop hook enforces the Legal Grounding Protocol: an answer must
not cite a norm or a decision that the session has not read with a tool. 3.0
redesigns it (#60), because the 2.x gate could be passed by accident in many
ways. What is new:

- **Norms are checked by act and article.** Reading «art. 2 Cost.» no longer
  covers «art. 2 c.p.»; one `cite_law` call covers only the article it served.
  The act can be written before or after the article («D.Lgs. 196/2003, art.
  13», «art. 6, par. 1, lett. f), del Regolamento (UE) 2016/679»).
- **Decisions are checked too**: Cassazione, Corte costituzionale, TAR and
  Consiglio di Stato, CJEU cases (`C-311/18`). A decision is covered only by
  that court's own reader or search, and only for the decision named in the
  result's heading: the precedents a decision cites, and Brocardi abstracts,
  cover nothing.
- **Everything written in the turn is read**: every text block, prose files
  written with Write/Edit, and the inputs of `esporta_atto_docx` and the
  `genera_*` tools. Subagents are checked as well, and their reads count for
  the main answer.

When the gate stops an answer, Claude sees a message that starts with
«ATTENZIONE — gate citazioni (Legal Grounding Protocol)» and lists the
sources it could not match, each with the tool to read it. There are two
correct answers:

1. read the source with the tool named next to it (`cite_law`,
   `leggi_sentenza`, `leggi_pronuncia_costituzionale`...), then finalise;
2. for a source no tool covers (the ECHR, the codice deontologico forense),
   write **«fuori copertura»** on the same line as the citation. References
   that do not look like law, such as «art. 5 del contratto», are not
   checked at all.

The gate stops an answer at most once per turn, never blocks on its own
error, and reads the session transcript locally. Limits, stated: it checks
that a source was read, not what the answer says about it; acts cited without
an article («il GDPR prevede...») are not checked; credit is session-wide.

To switch the gate off, and only the gate, set `LEGAL_CITATION_GATE=off`
(`0`, `false` and `no` work too), for instance with
`"env": {"LEGAL_CITATION_GATE": "off"}` in a project's
`.claude/settings.local.json`. It is meant for software-development sessions
that quote norms in code or docs; keep it on for legal work.

## 3. Claude Desktop `.mcpb` users

- **Update**: download `legal-it-3.0.0.mcpb` from the
  [GitHub release](https://github.com/capazme/mcp-legal-it/releases/latest)
  and install it as the first time: double click on the file, or drag it onto
  Claude Desktop → Settings → Extensions. It replaces the installed version.
- **FastMCP**: the extension now pins `fastmcp>=3.4,<4` (it was `>=2.0`,
  older than what the server needs). Its `uv` environment is rebuilt once, at
  the first start of 3.0: give it a minute.
- If the tools answer «[Errno 2] No such file or directory» after the update,
  the uv cache was cleaned under the running server: disable and re-enable
  the extension.
- If you also use the Claude Code plugin in the **Code** tab of the Claude app,
  keep only one of the two, or the tools appear twice.

## 4. uvx, pip and library users

### 4.1 Running the server

The distribution and the console script are still called `mcp-legal-it`:

```bash
uvx --from git+https://github.com/capazme/mcp-legal-it@v3.0.0 mcp-legal-it
```

Library installs accept FastMCP 3.4 to 4.x (`fastmcp>=3.4,<5`). The plugin
lock resolves FastMCP 3.4.9.

### 4.2 BREAKING: the import package is `mcp_legal_it`

The Python package is no longer called `src`. A published package must not
own that name: installed next to any project whose own code is a `src`
package, one shadows the other.

| 2.x | 3.0 |
|---|---|
| `from src.tools.varie import ...` | `from mcp_legal_it.tools.varie import ...` |
| `python -m src` | `python -m mcp_legal_it` |
| `patch("src.lib.italgiure.client....")` | `patch("mcp_legal_it.lib.italgiure.client....")` |
| `plugin/server/src/` | `plugin/server/mcp_legal_it/` |

There is **no compatibility shim**: a shim would keep owning the colliding
name. The repository-root `src` symlink is gone. The only visible change in an
MCP answer is that `backlog_riconciliazione` names a table as
`mcp_legal_it/data/<name>.json`.

### 4.3 `crea_server`: a subset of the tools

```python
from mcp_legal_it.server import crea_server

# norms and case law only, no calculators, no Brocardi
fonti = crea_server(include_tags={"normativa", "giurisprudenza"}, brocardi=False)
fonti.run()                       # standalone
# or: my_server.mount(fonti, namespace="legal")
```

Signature: `crea_server(include_tags=None, exclude_tags=None, brocardi=True, *,
name="Legal IT", prompts=True)`. Excluded tools are absent from `list_tools`;
kept tools are identical to the stock ones. Unknown tags raise `ValueError`.
`exclude_tags={"brocardi"}` is not `brocardi=False`: it drops every tool that
*can* show Brocardi, `cite_law` included. Environment switches
(`LEGAL_PROFILE`, `LEGAL_BROCARDI=off`...) still apply underneath and can only
narrow the selection.

### 4.4 `mcp_legal_it.api`: the only stable surface

From 3.0, **`mcp_legal_it.api` is the package's only stable (semver) surface**.
Everything else (`tools`, `lib`, `core`, `server` internals) can change in any
release. The API returns typed frozen dataclasses with no Markdown, reports
errors as data (`esito` plus `errore`), carries the provenance of every network
result (`fonti`) and imports neither FastMCP nor the server. Reference,
configuration and deprecation policy: [`docs/api.md`](../api.md).

If your code imported `src.tools.*` or `src.lib.*` to reach a reader, move it
to the API where the function exists there; otherwise pin the exact 3.0.x
version you tested.

Planned API operations (act tree, recitals, decision PDF, multi-article
references, the `html` text channel...) are declared in `docs/api.md` §6 and
kept out of `__all__` until the VisuaLex migration delivers them.

## 5. Docker and HTTP deployments

### 5.1 The image

There is no published image: build it from the repository.

```bash
docker build -t mcp-legal-it .
docker run -p 8000:8000 mcp-legal-it          # Streamable HTTP on /mcp
docker compose up                             # same, with a cache volume
```

What changes:

- The image installs the package and runs the `mcp-legal-it` entry point.
- **It runs as an unprivileged user** (`legal`, uid 10001). A `mcp-cache`
  volume created by a 2.x image is owned by root: `chown -R 10001` it or
  recreate it, otherwise the server runs without the disk cache.
- Generated documents (procure, quotazioni, atti, supplier reports, law PDFs)
  go to a private `0700` folder under the temp directory. A symlink there, or
  a folder owned by another user, is refused.

### 5.2 Network rules

Every outgoing request, redirects included, is checked before it leaves:
http(s) only, no credentials in the URL, and a host the source is allowed to
reach. A refused request never reaches the network. On top of that, per
source:

- at most 3 requests in flight and 0.5 s between two requests;
- a `Retry-After` from a 429 or 503 pauses that source for every caller, for
  at most 30 s; a longer statement refuses that call at once;
- a 429 is retried within the retry budget (2 retries), waiting what the
  source asked;
- optional circuit breaker, `LEGAL_CIRCUIT_BREAKER=on` (off by default): 3
  consecutive failures suspend the source for 5 minutes; a 404 never counts.

**The limits are per process.** N worker processes on one machine make N times
the cap. If you scale out, size the number of processes with that in mind.

### 5.3 Security fixes that matter on HTTP

On stdio the caller is your own Claude session; on HTTP it can be any client
that reaches the port. These fixes close what such a client could exploit:

- **SSRF in `leggi_sentenza_cgue`**: the `cellar_uri` argument was fetched as
  given, so a client could make the server read localhost, cloud metadata or
  an intranet. Only `http(s)://publications.europa.eu/resource/...` is accepted
  now, refused before any request, and a redirect may not leave CELLAR.
- The host guard of §5.2 applies to every reader, so no tool can be steered to
  an arbitrary host. The one tool that contacts a host chosen by the caller,
  `verifica_dpa_fornitore`, accepts only public registrable names and checks
  every resolved address and every redirect.
- Italgiure is reached over **verified TLS** (it used `verify=False`): the
  missing intermediate ships with the package and is checked against its
  SHA-256 pin at runtime.
- The `_egress` allowlist refuses backslashes, control characters, credentials
  and non-http(s) schemes.

The HTTP transport has **no authentication of its own**. Expose it only behind
a reverse proxy that authenticates callers, or on a private network.

## 6. Behaviour changes a lawyer must know

Every item below changes an answer. Each norm cited here was read on the text
in force (Normattiva, 2026-10-21).

| Tool | 2.x | 3.0 | Why |
|---|---|---|---|
| `termini_esecuzioni` | `tipo="opposizione_esecuzione"` computed the 20-day term of art. 617 c.p.c. | That name is **removed** and returns an error listing the accepted values; use `tipo="opposizione_atti_esecutivi"` | The old name read as the opposition to enforcement (art. 615 c.p.c.), which has no such term; the 20 days are the opposition to enforcement acts (art. 617 c.p.c.) |
| `termini_separazione_divorzio` | The 6/12 months of separation were extended to the next working day when they ended on a Saturday or a holiday | No extension; the result carries a `nota` | The months of art. 3 n. 2 lett. b) L. 898/1970 are a minimum duration of the separation, not a deadline for an act, so art. 155 c.p.c. does not apply (owner's legal reading). Example: 12 months from 15/03/2025 end on Sunday 15/03/2026, no longer on Monday 16/03/2026 |
| Deadline tools (`giorno_settimana`) | Weekday name followed the computer's language: «lunedì» or «Monday» | Always Italian | Same dates; only the name was wrong |
| `cite_law`, `fetch_law_article`, API | «art. 3-5 c.c.» became art. 35, served as found | Any article range is refused: «chiedere un articolo alla volta» | A range is two requests; reading it as one article was a silent wrong answer |
| `cite_law` | «D.Lgs. 196/2003 art. 13» returned art. 1 of the act, with no warning (same for an annex written after the act) | The act-first form is parsed; an article that cannot be told apart from the act is refused | Wrong article served in silence |
| `verifica_citazioni` | «Corte cost. n. 238/2014», «Cons. St. n. 1/2020» were searched on Italgiure and reported «inesistente» | Corte costituzionale is checked on its own archive; Consiglio di Stato, TAR, CJEU, Corte dei conti, ECtHR, tax and merits courts (giudice di pace included) are «non verificabile», with the tool to search them | A decision that exists was reported as not existing |
| `giurisprudenza_su_norma` | «art. 25-terdecies d.lgs. 231/2001» searched art. 25-ter | Searches art. 25-terdecies; suffixes run to «vicies» | The suffix table stopped at «decies» |
| Content of several tools | — | Non-cumulation of default interest and revaluation: art. 1224 co. 2 c.c.; giudice di pace thresholds 10.000 / 25.000 euro (art. 7 c.p.c.); comparse conclusionali and memorie di replica under art. 189 c.p.c.; compensatory interest not on the fully revalued sum | Aligned with the text in force |
| Citations of the disp. att. c.p.c. | Dated 25/08/1941 | Dated 18/12/1941 (R.D. n. 1368) | Wrong date in the act table |
| `termini_deposito_atti_appello` (appellee's comparsa, and so the cross-appeal deadline of art. 343 c.p.c.) | 70 days before the hearing (art. 166 c.p.c., as the first Cartabia text of art. 347 implied) | **20 days** before the hearing (art. 347 co. 1 c.p.c. as amended by D.Lgs. 164/2024); the answer cites art. 347 and art. 343 and, for appeals introduced between 28/02/2023 and 26/11/2024, adds `avvertenza_regime_transitorio` (in that window art. 347 still pointed to the 70 days: the lawyer assesses whether the 20 days apply backwards). The same warning appears when the date of notification of the citation is not given | Art. 347 co. 1 in force says «almeno venti giorni prima dell'udienza»; before 28/02/2023 the term was already 20 days. The 70 days of the first-instance comparsa (art. 166) are unchanged |
| D.M. 55/2014 fees at `livello='min'` and `livello='max'` (`parcella_avvocato_civile`, `parcella_avvocato_penale`, `parcella_stragiudiziale`, `parcella_volontaria_giurisdizione`, the `preventivo_*` tools, `calcolo_notula_penale`, `modello_notula`) | The minimums and maximums of the table were rounded to the euro in many cells (for example 131 → minimum 66, maximum 197) | The minimum is exactly half of the medium and the maximum exactly one and a half, **to the cent** (131 → 65,50 and 196,50); the medium stays rounded to the euro, as the table transcribes it | Art. 4 co. 1 D.M. 55/2014: the medium is reduced «in ogni caso non oltre il 50 per cento» and increased «fino al 50 per cento». A minimum rounded up overstates the floor and a maximum rounded up the ceiling |
| The nine deadline tools that apply the August suspension (`scadenza_processuale`, `termini_processuali_civili`, `scadenze_impugnazioni`, `scadenze_multe`, `termini_memorie_repliche`, `termini_procedimento_semplificato`, `termini_183_190_cpc`, `termini_deposito_atti_appello`, `termini_deposito_ctu`) | Two of them appended a fixed sentence on excluded matters to every answer; the others said nothing | When the suspension moved the result they add `avviso_sospensione_feriale`: recompute with `sospensione_feriale=False` if the case is excluded, with the excluded matters and their source (art. 3 L. 742/1969: labour and social security; art. 92 R.D. 12/1941: alimenti, cautelari, amministrazione di sostegno, interdizione e inabilitazione, ordini di protezione, sfratto, opposizione all'esecuzione, dichiarazione e revoca dei fallimenti, materia corporativa, cause dichiarate urgenti). When it changed nothing there is no notice, and the fixed sentence is gone | The lawyer is told when the suspension mattered and what it does not cover, instead of a generic line on every answer |
| `termini_esecuzioni` (opposition under art. 617 c.p.c.) | The 20 days were computed without the August suspension, with no comment | Same computation (the prudent reading), plus `avvertenza_sospensione_feriale` when August falls inside the 20 days | Whether art. 617 is excluded from the suspension is debated: art. 92 R.D. 12/1941 names only the «opposizione all'esecuzione». The warning leaves the choice to the lawyer (see §7) |
