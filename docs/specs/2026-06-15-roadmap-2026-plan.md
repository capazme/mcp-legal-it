# Roadmap 2026 — Master implementation plan

- **Date**: 2026-06-15
- **Branch**: `feature/roadmap-2026` (epic, from `develop`)
- **Goal**: implement roadmap items 1–7 with maximum speed, stability, and practical usability.
- **Method**: recon-first (live-source mapping) → reviewed design → phased build with verification gates → integration → release. Mirrors the AKN feature, which succeeded because structure was discovered before code was written.

## Source of truth

The roadmap (from the 2026-06-15 competitive analysis):

1. `verifica_citazioni` — citation verifier ("does this cite exist / is it quoted correctly?").
2. Scheduled "digest" agent — weekly Italian-law briefing over the `ultime_*` tools.
3. Corte Costituzionale — scraper (lib client + 3–4 tools). The one missing Italian jurisprudence source.
4. `orientamento_giurisprudenziale` — conforming vs conflicting case law on a principle (Sezioni Unite, contrasto). Unoccupied territory in Italy.
5. Cowork practicality — docx/pdf rendering skills for deliverables + port key MCP prompts to slash commands/skills.
6. Gazzetta Ufficiale + EU→IT implementation mapping + HTTP-first deployment for cloud routines + small default `LEGAL_PROFILE`.
7. Contract analysis & RAG — **architectural decision pending** (see Wave 4). Recommended: build in SAPG, not here.

## Guardrails (non-negotiable)

- **Stateless core preserved.** mcp-legal-it stays a stateless legal-tools server across stdio/HTTP/SSE. Anything requiring persistent storage (RAG index, uploaded-file corpus) does NOT belong here — it belongs in SAPG. This gates Wave 4.
- **Fail-safe + grounded.** New retrieval tools follow the Legal Grounding Protocol: return official-source text/links, never model-memory. New scrapers degrade visibly (clear Italian error), never silently.
- **Signatures stable.** New tools are additive; existing tool signatures unchanged.
- **Verification gates.** Each feature ships with unit tests (network mocked, real fixtures) and must keep the full suite green. No feature merges on red.
- **Git Flow.** Epic branch `feature/roadmap-2026`; each wave squash-friendly. Release as one MINOR (2.4.x → 2.5.0) when complete, via `release/2.5.0` → main + tag. All six version points bumped together (lesson from 2.4.1).

## Waves & dependencies

### Wave 0 — Recon & design (read-only; running now)
Parallel probes of every genuinely-unknown source; output is a structured feasibility + design per feature. No code written. Gates Waves 2–3. Covers:
- Corte Costituzionale site (search endpoint, result shape, full-text access).
- Gazzetta Ufficiale (search/fetch, machine-readable availability).
- Orientamento data (what Italgiure facets / citation links + Brocardi massime allow).
- EU→IT mapping source (EUR-Lex national transposition / CELLAR "national implementing measures").
- Existing-surface inventory for the no-recon features (citation verifier, digest, docx, prompt-porting).

### Wave 1 — Foundations & quick wins (no external recon needed; can start immediately after Wave 0 inventory)
- **F1 `verifica_citazioni`** — new tool in `legal_citations.py` (or `verifica.py`). Input: list of references (sentenze + articoli). Resolves each via `leggi_sentenza` / `cite_law`; flags non-existent or misquoted. Pure recomposition of existing tools. Tests with mocked resolvers.
- **F5a docx/pdf rendering skills** — extend the `docx-sapg` pattern so privacy/atti/parcelle deliverables render to a finished file in the active folder under Cowork. Skill-level, no server change.
- **F5b prompt → command/skill port** — port the highest-value MCP prompts (`parere_legale`, `analisi_giurisprudenziale`, `compliance_privacy`) to plugin slash commands/skills so they survive in Cowork (which may not surface MCP prompts).
- **F2 digest scheduled agent** — a plugin agent (cron frontmatter) that runs `ultime_pronunce` / `ultime_delibere_consob` / `ultime_sentenze_tributarie` / `ultimi_provvedimenti_amm` / `ultime_sentenze_cgue` and writes a weekly briefing. No server change.
- **F6-infra** — document HTTP-first deployment for Cowork/cloud routines; add a small default `LEGAL_PROFILE` recommendation to cut the 201-tool context tax.

### Wave 2 — New data-source scrapers (recon-gated)
- **F3 Corte Costituzionale** — `src/lib/corte_cost/client.py` + 3–4 tools (cerca, leggi, su_norma, ultime), mirroring the existing scraper modules. Fixtures from real pages.
- **F6a Gazzetta Ufficiale** — `src/lib/gazzetta/client.py` + tools. Recon confirmed full scraper is tractable (no XML/AKN; HTML + ELI RDFa metadata + official PDF). **RSS feeds exist and are the stable path for "latest"**: `https://www.gazzettaufficiale.it/rss/{SG|S1..S5|P2}` (application/rss+xml) — each `<item>` = title (issuer+type+date), `<link>` = ELI permalink (carries codiceRedazionale+date), description, pubDate. Design: `ultime_gazzette` reads RSS; full-text fetch follows the ELI link via the existing detail/menu/article path; parametric SEARCH stays on the HTML POST `/do/ricerca/atto`. The Gazzetta RSS also feeds the F2 weekly digest as a "novità normative" source.

### Wave 3 — Analytical / derived features
- **F4 `orientamento_giurisprudenziale`** — builds on existing Italgiure + Brocardi: given a principle/massima, retrieve conforming vs conflicting later decisions, surface SS.UU. interventions, flag contrasto. **Descriptive, not predictive** (Law 132/2025 reserves legal interpretation to magistrates).
- **F6b EU→IT mapping** — `get_italian_implementation(directive)` / `get_eu_basis(act)` using CELLAR/SPARQL (already used for CGUE).

### Wave 4 — Item 7 (contract analysis) — DECIDED: stateless single-shot only
User decision (2026-06-15): add a **stateless contract-analysis tool** to mcp-legal-it; RAG stays in SAPG.
- **F7 `analizza_contratto`** — operates on contract TEXT passed in the tool call (no storage, no upload, no index). Extracts clauses, flags missing/atypical ones against a built-in Italian checklist (e.g. foro competente, recesso, penali, riservatezza, trattamento dati ex art. 28 GDPR), and returns a structured markdown review. Optionally cross-links cited norms via `cite_law`. Pure function over input text — preserves statelessness and works identically across all 3 transports.
- **Out of scope (explicitly):** RAG over the user's own document corpus, file ingestion/upload, persistent clause libraries, redline injection into files. These remain in the stateful SAPG platform.

### Wave 5 — Integration & release
- Single-writer integration step wires all new modules into `server.py` (avoids parallel-edit conflicts), updates `instructions`, profiles, docs/CLAUDE.md tool counts.
- Full suite green; bump all six version points to 2.5.0; `release/2.5.0` → main + tag; submodule pointer note for the parent repo.

## Risk register

- **Live-site fragility** (Corte Cost, Gazzetta): anti-bot / structure drift. Mitigation: recon-first, HTML fixtures, fail-safe errors, `@pytest.mark.live` only for E2E.
- **Parallel file conflicts** in the build workflow: each feature writes DISTINCT new modules; `server.py` wiring is centralized in Wave 5.
- **Context tax** of more tools: mitigate via `LEGAL_PROFILE` and (where supported) Tool Search; group new tools under existing profiles.
- **Cowork uncertainty** (hooks/prompts/resources support): F5b removes the dependency by porting to commands/skills; verify in a real Cowork install.
- **Scope creep**: Wave 4 gated; orientamento kept descriptive.

## Execution model

Wave 0 = a recon workflow (now). Waves 1–3 = build workflows launched after recon returns and item 7 is decided, each using the pipeline pattern recon-design → implement+test → verify, with `server.py` integration centralized. The user reviews between waves (stability over one-shot).
